# Section

Section six carries no table, whichever of REGISTERS, METHODS, PRIMITIVES and INTERFACES it is. REGISTERS holds the registers, bitfields and fields the page's paths touch, each drawn in one of the DWORD-grid or L-connector style with the prose beside it saying what each field decides on this page's paths.

The functions that read or write them are catalogued in COVERAGE where this page owns them and named in DETAILS at the stage they run.

A register is drawn on every page whose paths touch it, the same figure on as many pages as share it, since a drawing is never one page's; only the catalog entry is: a register no other page's scope names, and that the cluster boundary gives to no other page, is this page's catalog entry, with its definition excerpt, under a COVERAGE heading that names the register block and its header.

The section carries no table: a row per register with its helper, bits and meaning is a bit layout that needs a drawing, and it is drawn.


The DWORD-grid style places field names inside cells and stacks successive DWORD rows for multiword structures. The L-connector style places a single register on one row with one-character bit cells and L-shaped leaders below for mostly single-bit fields. A register is one value at one address, however wide; a structure has successive DWORD rows.
